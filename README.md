# Director Studio

Браузерная мастерская для постановки 3D-сцен, поиска ракурсов и создания раскадровок. Интерфейс на русском. Первая версия работает локально, без сервера, регистрации, API-ключей, аналитики и внешних ассетов. Сцены и файлы не отправляются на внешние сервисы.

## Запуск

Нужен Node.js 22.12+ (в облачной среде проверено с Node.js 24) и npm.

```bash
npm ci
npm run dev
```

Откройте адрес, указанный Vite в терминале. Для работы нужен актуальный Chrome или Edge с WebGL 2 и включённым аппаратным ускорением. Установка Node.js нужна только разработчику: пользователю опубликованного приложения достаточно браузера.

```bash
npm run build       # проверка TypeScript и production-сборка в dist/
npm run preview     # локальная проверка production-сборки
npm test            # тесты данных, снимков, камер и интерполяции
npm run test:e2e    # реальные пользовательские сценарии в Chromium
```

Браузерные тесты используют системный `/usr/bin/chromium`, если он существует. На другой машине выполните `npx playwright install chromium`. Можно явно задать `CHROMIUM_PATH`. В Linux CI при необходимости установите системные зависимости командой `npx playwright install --with-deps chromium`. Тесты включают программный WebGL и запускаются последовательно, поскольку PNG-рендеринг использует GPU / CPU.

## Первые шаги

1. При первом запуске открывается «Разговор в офисе»: два героя, стол, стул, стена, дверь, пять камер и три кадра.
2. Выберите персонажа слева или в сцене. Переместите его стрелками, измените числовые координаты, рост, цвет, поворот, позу и положение рук. В параметрах также доступны шесть локальных вариантов силуэта / аксессуара и короткая метка для раскадровки. Поворот головы независим от корпуса. Команды «Повернуться» и «Посмотреть» используют выбранного второго персонажа.
3. Выберите съёмочную камеру. Обзор редактора независим: его вращение не меняет ракурс съёмки. Камеру можно перемещать и поворачивать манипуляторами или числовыми полями, включая положение у пола и наклон горизонта.
4. Выберите наведение на героя / точку либо ручной поворот. Изменение объектива не двигает камеру. Форматы: 16:9, 9:16, 1:1.
5. «Войти в камеру» включает WASD, Q/E и поворот взгляда при зажатой ЛКМ. Shift ускоряет движение, Esc выходит. При входе наведение переключается на ручное с сохранением текущего направления. Весь сеанс управления отменяется одним действием.
6. Пресеты — отправные точки. Для планов на двоих / через плечо выберите героя в кадре и второго героя. Для реакции пресет направляется на второго. Параметры остаются редактируемыми; пересечение линии взаимодействия не запрещено.
7. Нажмите «Сохранить кадр». Кадр содержит отдельный снимок всех объектов, поз и камер. Выбор кадра восстанавливает сцену. Только явная команда «Обновить кадр текущей сценой» заменяет его снимок. Под кадрами доступны название, реплика, длительность, копирование, порядок и удаление.

Меню «Добавить объект» разделено на персонажей, мебель, реквизит и помещение. Помимо прежних объектов доступны кресло, небольшой и рабочий стол, ресепшен, стеллаж, монитор, кружка, телефон, бумаги, коробка, окно и перегородка. Новые предметы поддерживают обычные координаты, поворот, копирование и удаление.

Кнопка «Вид» внутри обзора переключает сетку, имена персонажей, подписи камер и линии обзора. Эти настройки относятся только к редактору и не входят в отдельные PNG.

Панели сворачиваются кнопками над сценой; предпросмотр увеличивается кнопкой в его заголовке. Виды сверху, спереди, сбоку и перспектива доступны над 3D-обзором. «Вернуть удобный обзор» сбрасывает только обзор редактора.

### Клавиши

| Действие               | Клавиши                 |
| ---------------------- | ----------------------- |
| Перемещение / поворот  | G / R                   |
| Удаление объекта       | Delete / Backspace      |
| Дублирование           | Ctrl D (на macOS Cmd D) |
| Отмена                 | Ctrl Z                  |
| Повтор                 | Ctrl Shift Z / Ctrl Y   |
| Движение внутри камеры | W A S D                 |
| Подняться / опуститься | E / Q                   |
| Ускориться / выйти     | Shift / Esc             |

Горячие клавиши редактирования не работают во время ввода текста. Перетаскивание манипулятора считается одним действием отмены, вращение обзора во время него отключено. Хранится до 40 действий в памяти; история отмены не входит в JSON.

## Движение

Во вкладке «Движение» сохраните ключ при 0 с. Передвиньте ползунок на другое время, нажмите «Редактировать этот момент», измените сцену и сохраните следующий ключ. Добавление ключа в существующий момент заменяет его снимок. Крестик у ключа удаляет его.

Поддерживаются два и более ключа, длительность до 120 с, линейная / плавная интерполяция, воспроизведение, пауза и перемотка. Интерполируются координаты и ориентация камеры, фокусное расстояние, координаты и поворот персонажей. Повороты камеры используют quaternion slerp, поворот корпуса — кратчайшую дугу. Камеры с наведением следят за интерполируемой целью. Поза, состав сцены и выбранная камера меняются на границе ключа, а не морфируются.

«Ручная камера» добавляет детерминированное лёгкое колебание к просмотру движения и экспорту, не меняя сохранённых координат. Интенсивность регулируется. Анимация — блокинг без походки, физики и сложного рига.

## Сохранение и экспорт

- Автосохранение через 700 мс после изменения в IndexedDB; сверху отображается статус. «Сохранить» записывает немедленно. При ошибке / нехватке места скачайте JSON.
- «Открыть» показывает локальные проекты. Перед удалением требуется подтверждение. Переключение проекта сначала сохраняет текущий; при отказе хранилища появляется предупреждение о потере изменений.
- JSON содержит версию `1`, проект, сцену, камеры, кадры, миниатюры и ключи. Новые постановочные поля, силуэт и метки необязательны; отсутствующий силуэт получает базовое значение. Дополнительные предметы сохраняются как варианты прежних типов, структура v1 не заменяется. Старые проекты открываются, сцены и камеры сохраняются. Импорт ограничен 50 МБ и проверяется Zod до замены открытого проекта. Импорт создаёт отдельную локальную копию. Некорректный файл не меняет сцену.
- PNG текущего вида / выбранного сохранённого кадра рендерится отдельно от редактора. Сетка, манипуляторы и значки камер отсутствуют. Full HD: 1920×1080, 1080×1920 или 1920×1920 в зависимости от формата. Доступны также 1280 и 800 по длинной стороне.
- Все кадры можно скачать отдельными PNG в ZIP или контактными PNG-листами. На каждом листе до шести равных ячеек, порядок чтения слева направо и сверху вниз. Форматы 16:9, 9:16 и 1:1 сохраняются внутри ячейки целиком: изображение не обрезается и не растягивается. Крупные номера, накопительный тайминг, тип плана / название, фактический формат и короткие действия / реплики читаются без уменьшения шрифта. Более шести кадров дают несколько PNG-листов в ZIP. Длинные подписи на листе сокращаются; полный текст сохраняется в плане и JSON. Имена и короткие метки можно отдельно включить в подписи листа, за пределами изображения.
- Движение экспортируется последовательностью PNG в ZIP с частотой 6, 12 или 24 кадра/с. Последнее изображение — конечный ключ. Видеокодирования и звука нет. Максимум 241 изображение за экспорт; уменьшите длительность / FPS для длинного движения. Экспорт выполняется в памяти браузера, для больших проектов используйте черновое разрешение.

**Локальные проекты привязаны к браузеру и адресу сайта.** Очистка данных сайта или приватный режим могут удалить их. JSON — переносимая резервная копия. Переезд сайта на другой домен не переносит IndexedDB: используйте экспорт / импорт.

Рабочие ограничения v1: 200 объектов, 50 камер, 100 кадров раскадровки, 100 ключей. Основной интерфейс рассчитан на компьютер и мышь; на узком экране сверните боковые панели. Нет сложной скелетной анимации, импорта сторонних 3D-моделей, совместного редактирования, генеративного ИИ или интеграции с Seedance.

## Пакет для Seedance

Выберите сохранённый кадр и откройте «Постановка кадра», если хотите указать тип плана, говорящего, действие / реакцию, описание движения камеры и переход к следующему кадру. Эти поля необязательны. Наведение камеры не означает, что персонаж говорит; приложение не угадывает реплики, действия, тип плана или склейку. Описания движения и перехода передают замысел и сами по себе не создают анимацию.

В карточках и плане автоматически рассчитывается накопительное время: длительности 2 с и 3 с дают интервалы `00:00–00:02` и `00:02–00:05`. Дробные секунды сохраняются. Перестановка, дублирование и изменение длительности пересчитывают интервалы в новом порядке.

Нажмите **«Экспорт» → «Экспорт для Seedance»**. По умолчанию отдельные кадры экспортируются с длинной стороной 1920 px; при необходимости выберите другое разрешение. Формат каждой сохранённой камеры сохраняется независимо от текущей сцены и других камер.

ZIP содержит:

- `storyboard-01.png`, `storyboard-02.png`, … — читаемые контактные листы, до шести кадров на странице, с общей нумерацией.
- `01_00-02s_Название-плана.png`, … — полноразмерные PNG из собственных снимков сцен и камер. В изображениях нет редакторской сетки, имён, манипуляторов или линий обзора.
- `shot-list.txt` — номер, точное время, название и тип плана, формат, говорящий, реплика / заметка, действие, движение камеры и переход. Неуказанные поля помечены «не задано».
- `shot-list.json` — версия плана, структурированные кадры и полный проект v1 в поле `project`. Это обёртка плана, не замена обычному импортируемому JSON; для прямого переноса используйте «Проект · JSON».
- `README.txt` — рекомендация по использованию.

Ключевая анимация проекта имеет свою шкалу времени. Если в ней есть изменения камер, план перечисляет реальные изменения положения, направления и фокусного расстояния в отдельном разделе. Приложение не приписывает это движение произвольным кадрам раскадровки. Для конкретного кадра можно отдельно заполнить описание движения.

Рекомендация: загрузите листы в Seedance как визуальный референс и отдельно укажите порядок кадров и тайминг в текстовом запросе. Например: «Кадры читаются слева направо, сверху вниз. Кадр 01: 0–2 с, общий план. Кадр 02: 2–5 с, крупный план. Сохраняй различия и цвета персонажей по референсам». Это пример инструкции, а не автоматически созданный сценарий. Точное соблюдение моделью всех кадров и времени не гарантируется. Director Studio не связывается с Seedance: файлы загружает пользователь вручную.

На листе длинный текст сокращается до двух строк, а в текстовом плане остаётся полностью. Шесть карточек на странице сохраняют читаемость при большом числе кадров. Экспорт выполняется в памяти браузера; для больших проектов доступно черновое разрешение. Видеокодирование не добавлялось.

## Cloudflare Pages

Приложение полностью статическое. Публикация не требует backend, Functions, базы данных или секретов.

1. В своём аккаунте Cloudflare создайте проект **Workers & Pages → Pages**, подключите репозиторий и выберите ветку с приложением.
2. Укажите корневую папку репозитория (там, где `package.json`). Framework preset: **Vite**, либо **None**.
3. Build command: **`npm run build`**. Build output directory: **`dist`**.
4. Установите переменную сборки **`NODE_VERSION=24`**, если версия Node в настройках отличается. Зависимости фиксируются `package-lock.json`; для собственного CI используйте `npm ci`.
5. Выполните Deploy в интерфейсе Cloudflare. Для ручной загрузки сначала соберите локально и загрузите содержимое `dist` через Pages Direct Upload.

Маршрутизация находится на одной странице: дополнительных rewrite-правил не требуется. В `public/_headers` заданы заголовки для статического сайта, включая запрет запросов к сторонним сервисам. Изменения исходников требуют новой сборки. Проверка Chrome/Edge на Windows и реальная публикация на Cloudflare выполняются отдельно: облачные браузерные тесты используют Chromium на Linux.

## Структура

- `src/model.ts` — JSON-модель, валидация, демонстрация, пресеты, интерполяция.
- `src/world.ts` — геометрия, свет и единая настройка съёмочной камеры.
- `src/components/Viewport.tsx` — независимые R3F-виды, выделение, манипуляторы, управление из камеры.
- `src/components/Inspector.tsx` — параметры персонажей, предметов и камер.
- `src/components/CameraPanel.tsx`, `ProjectHeader.tsx`, `ProjectDialogs.tsx`, `SceneList.tsx` — предпросмотр, пресеты, файловые команды, проекты и список сцены.
- `src/components/Timeline.tsx` — раскадровка и ключевые кадры.
- `src/storage.ts`, `src/useProject.ts` — IndexedDB, автосохранение, история.
- `src/export.ts` — PNG, ZIP, листы, пакет Seedance и последовательность кадров.
- `src/storyboard.ts` — накопительное время, нумерация, структура / текст плана и раскладка страниц.
- `src/catalog.ts` — локальные силуэты и каталог совместимых вариантов предметов.
- `src/components/FrameInfo.tsx`, `EditorDisplay.tsx`, `SeedanceGuide.tsx` — постановочные поля, настройки обзора и справка.
- `src/App.tsx` — компоновка и пользовательские команды.
- `src/model.test.ts`, `tests/editor.spec.ts` — модульные и браузерные проверки.

В JSON не сохраняются экземпляры Three.js. Их создание и освобождение отделены от данных проекта. Экспорт ждёт компиляции материалов и завершает синхронный рендер перед чтением canvas.

## Выполненная проверка первой версии

Проверены чистая установка `npm ci`, строгая проверка TypeScript и production-сборка. 11 модульных тестов проверяют JSON, независимость снимков, удаление цели, пресеты, интерполяцию и отсутствие накопления дрожания. Браузерные сценарии в Chromium/Linux проверяют автосохранение после перезагрузки, обратный импорт JSON и отказ некорректного импорта, независимость обзорной камеры, снимки кадров, перетаскивание и отмену одним действием, создание камеры из обзора, воспроизведение раскадровки, анимацию, управление WASD и Esc, PNG/ZIP/лист, а также ошибки IndexedDB и WebGL.

В экспортированных PNG проверяются фактические размеры, непустое изображение и соответствие предпросмотру. Отдельно проверяются пропорции всех трёх форматов в обычной и увеличенной панели. Windows / Edge и реальный хостинг Cloudflare в этой среде не запускались. Сборка выдаёт неблокирующее предупреждение Vite о размере основного 3D-бандла (около 378 КБ gzip).

## Проверки доработки для Seedance

Для совместимости сохранён `tests/fixtures/project-v1.json`, созданный кодом предыдущей версии. Модульные тесты проверяют открытие этой версии, безопасные значения необязательных полей, накопительное время, порядок страниц, отсутствие выдуманных постановочных данных, пропорции изображений, внешний вид и сохранение предметов. Браузерные проверки дополнены сценарием смешанных форматов и нескольких страниц ZIP, сравнением изображений на листе с отдельными PNG и восстановленным кадром, сохранением манекенов / предметов и управлением меню экспорта. Проверки запускаются теми же командами `npm test`, `npm run build`, `npm run test:e2e`.

В доработке успешно выполнены `npm test` (24 теста), `npm run build` и все 9 браузерных сценариев в Chromium/Linux — в отдельных запусках с повтором затронутых проверок после исправлений. Дополнительно проверена собранная версия с CSP из статических заголовков: импорт проекта v1 и экспорт листа со смешанными форматами, без ошибок JavaScript. Новый контактный лист просмотрен визуально. Проверка Windows / Edge и публикация приложения не выполнялись.
